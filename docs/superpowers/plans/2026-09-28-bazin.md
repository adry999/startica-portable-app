# Bazin (23) — plan tehnic scurt

Modul nou, per filială, urmează convenția `records(kind,id,payload)` deja folosită de `groups`/`children`/`expenses` (nu depozitul separat al lui Personal — Bazin nu e comun ambelor filiale).

## Schemă (`src/shared/domain/record-schema.mjs`)

- `pool_settings` — un singur rând per filială, id fix `'pool-settings'`. Câmpuri: `pricePerSession` (150), `durationMin` (45), `hoursFrom`/`hoursTo`, `seatsPerSlot` (6), `chargeUnexcusedAbsence` (true), `coachPayMode` ('per_child'|'per_session'), `coachRate` (60).
- `pool_bookings` — `id`, `childId`, `coachId`, `weekday` (1-5), `time` ('HH:MM'), `startDate`, `endDate?`, `archivedAt?`.
- `pool_sessions` — `id`, `bookingId`, `date`, `status` ('present'|'absent'|'excused'). Generate on-demand (nu pre-populate) când se afișează săptămâna — o sesiune fără rând = neconsemnată încă, tratată ca „present” implicit conform 22a? Spec zice clic ciclează Prezent→Lipsă→Motivat, deci implicit (fără rând) = neconsemnat, UI arată gol, primul clic scrie 'present'.
- `pool_month_closures` — `id` (`<branchId ignorat, e per fișier>-YYYY-MM`), `month`, `closedAt`, `coachPay: { staffId, amount, rate, sessionsHeld, childrenPresent, mode }[]`, `childCharges: { childId, amount }[]`. Sursa de adevăr pentru `readCoachPayForMonth` (Personal arată „de închis în Bazin” până există o închidere pentru luna cerută) și pentru rândul „Bazin” din Situația plăților. Reînchiderea aceleiași luni (`closeMonth` idempotent) suprascrie rândul existent (nu dublează).

## Backend

1. `src/features/pool/domain/pool-schema.mjs` — validare payload per kind (nume/tip), calcul capacitate (`seatsPerSlot`), calcul sumă copil (prezențe×preț + lipsă nemotivată dacă `chargeUnexcusedAbsence`, motivat=0), calcul plată antrenor (per_child: rate×copii prezenți distincți/sesiune; per_session: rate×ședințe ținute).
2. `src/features/pool/server/pool.repository.mjs` — CRUD pe cele 4 kinds prin `recordRepository`.
3. `src/features/pool/server/pool.routes.mjs` — rute: settings (get/put), bookings (list/create/archive, cu verificare capacitate la create), sessions (list săptămână, toggle status), month (agregat + closeMonth idempotent).
4. `src/features/pool/server/read-coach-pay.mjs` — `readCoachPayForMonth(staffId, month)` citește din `pool_month_closures` (ultima închidere a lunii cerute), returnează intrarea coach-ului sau `null`.
5. Wiring în `create-branch-context.mjs`: `createPoolRoutes({...})` + pasează `readCoachPayForMonth: createReadCoachPayForMonth(recordRepository)` la `createPersonalRoutes(...)` (linia ~291, parametru azi lipsă → `undefined`).
6. Integrare Situația plăților: `src/shared/domain/tuition-obligation.mjs` rămâne neatins (pur, doar taxă); rândul „Bazin” se adaugă în UI (`StatusPage`/`useStatus`) ca linie separată citită direct din `pool_month_closures.childCharges`, nu vâră în `obligation()`.
7. Integrare Cheltuieli+Salarii: `closeMonth` scrie o cheltuială (categoria Salarii, ca în `salaries.service.mjs pay()`) pentru totalul plăților antrenorilor — NU dublează dacă `pay()` din Personal e apelat separat; antrenorul apare în lista Personal cu salariu = `readCoachPayForMonth`, plata efectivă (marcare „plătit”) tot prin `pay()` din Personal (Bazin doar alimentează calculul, nu plătește el însuși).
