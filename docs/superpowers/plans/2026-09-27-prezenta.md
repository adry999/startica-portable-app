# Prezența (ziua · luna · fișa copilului) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the „Prezența” module from `docs/design/screens/19-prezenta.md`: a SQLite table `attendance`, three server routes, a new page `/prezenta` with two modes — **Ziua** (18a: one tile per child, click cycles Prezent → Absent → Motivat → nemarcat, optimistic save with a 400 ms debounce) and **Luna** (18b: child × day grid for one group, print A4 landscape, .xlsx export) — and a „Prezența” section in the child profile. Attendance is bookkeeping only: it never touches fees, `obligation()` or „Situația plăților”.

**Architecture:** A new independent feature `src/features/attendance/` (domain + server, no other feature imported) with its own table in core `SCHEMA`, modeled on `sms-notify`. Pure rules (status cycle, who is enrolled on a day, day/month summaries) live in `domain/` and are consumed by `webapp/` through `#features/attendance/index.web.mjs`, like `#features/billing/index.web.mjs`. Legal holidays live in `#shared/domain/holidays-md.mjs` as the spec asks. In `webapp/`, the data hook and the dot component that both the page and the child profile need go under `webapp/src/shared/attendance/` (the same reason `webapp/src/shared/sms/` exists: `webapp/src/architecture.test.ts` forbids feature→feature imports); the page itself is `webapp/src/features/attendance/`.

**Tech Stack:** Node 22 vanilla ESM + `node:sqlite` + `node --test` on the server; React 19 + Vite + TypeScript + Vitest/RTL in `webapp/`; SheetJS (`xlsx`, already a webapp dependency, lazy-loaded) for the export. No new dependency.

**Spec:** `docs/design/screens/19-prezenta.md` (authoritative), `00-comun.md` (A, B, D, F), `docs/design/Prezenta.dc.html#18a` / `#18b` (visual reference only — spec wins), `docs/design/RASPUNSURI.md` point 13.

## Decisions (read before coding)

1. **Storage: dedicated table `attendance` in core `SCHEMA`, not a new `records` kind.** Volume is children × school days (≈ 100 × 22 × 12 ≈ 26 000 rows/year). Every `records` row is parsed by `readSnapshot()` on each `/api/state` and again in every `RevisionEnvelope` returned after a write (`revision-transaction.mjs:76`), so putting attendance in `records` would make every screen load and every save carry the whole attendance history. It would also force a new kind into `TYPES`, `normalizeRecord`, `validateState`, `upgradeSnapshot`, the Excel export/import and the V5 import. `sms_log` already set the precedent for feature tables outside `records`.
2. **Writes do not go through `runRevisionTransaction`.** That transaction exists for the versioned records: it bumps the global `revision` and refuses with 409 any tab that has not seen the latest state. The spec says the opposite for attendance: „la conflict pe aceeași zi câștigă ultima modificare, fără dialog”. A click is idempotent (an upsert to a target state), so `requestId` replay is unnecessary and `backupBefore` is irrelevant (nothing is irreversible — the next click undoes it). The repository runs its own `BEGIN IMMEDIATE … COMMIT` so a batch is atomic.
3. **No audit row per click.** ~100 clicks/day would bury the real record history in „Istoric” (`audit_changes` holds before/after JSON for children/payments). `attendance.updated_at` is the trace. If the lead wants it later, it is one `auditTrail.recordChange({ action: 'prezență', recordType: null, recordId: date, before, after })` per `POST` batch in the routes module.
4. **Backups include attendance, restore does not touch it.** `backup()` is `VACUUM INTO` of the whole file, so every backup carries the table. `/api/restore` calls `replaceAllRecords`, which only rewrites `records` — attendance stays as it is, same as `sms_log` today. Document it in the feature README; do not extend restore.
5. **No link to billing.** Acceptance criterion 4. The feature imports only `#shared/domain/calendar-month.mjs`, `#shared/domain/holidays-md.mjs`, `#core/server/errors/domain-error.mjs`; never `tuition-obligation.mjs`, `billing` or `fee-setup`. `obligation()` is not modified. Verified by grep in the last task.
6. **Filiale and sync are out of scope** (RASPUNSURI.md, closing line): no `branch_id`, no sync columns, no conflict metadata. Spec bullet 2 („Per filială… Se sincronizează…”) is deferred with Phase 6.
7. **Orphan rows are tolerated.** A permanently deleted child leaves its rows behind; the UI only renders children present in `records`, so they never show or count. No sweep in this plan.

## Spec ambiguities resolved here

- **„Înscriși după această dată nu apar”** → enrolled on `date` means `!child.archived`, `(attendanceDate ?? contractDate ?? '') <= date` and `(!withdrawalDate || withdrawalDate >= date)`. A child with neither date is included (unknown ≠ not enrolled). The withdrawal rule is not in the spec text but a withdrawn, unarchived child would otherwise stay „nemarcat” forever and inflate the card.
- **„Toată grupa prezentă”** marks **every** child of the group present, including those marked absent/excused — literal name and the mockup's behaviour (`set(kids, 'p')`). Only the header button „Toți nemarcații → prezenți” is restricted to unmarked children (acceptance criterion 2).
- **`POST /api/attendance` body** is `{ changes: [{ childId, date, status, reason }] }`, an object envelope around the spec's list (consistent with every other POST body; `status: null` = remove the mark, since „lipsa rândului = nemarcat”).
- **Month route** also accepts `childId` (`GET /api/attendance?month=&childId=`) — needed by the profile section for a child without a group; `groupId=none` selects children with `groupId: null`.
- **Profile section** shows the app's selected `month` (the same `month` prop the profile already uses for obligation); the excused-absence list covers that month.
- **Not built** because not in the spec: the „22 zile lucrătoare · prezență medie 86%” trailing text of the month filter bar, the yellow „Motivat cere un motiv…” hint box under 18a. Today's column highlight in 18b's header and a print-only caption („Prezența · <grupa> · <luna>”) are kept as styling, not elements.
- **Month grid population:** the group's children not archived whose start date ≤ last day of the month. A cell before the child's start date is blank and not a working day for that child.

### Task 4: Repository

**Files:** create `src/features/attendance/server/attendance.repository.mjs` + `.test.mjs`.

**Interface:** `createAttendanceRepository(database, { now = () => new Date() })` →

- `listByDate(date): AttendanceEntry[]`
- `listByMonth(month, childIds: string[] | null = null): AttendanceEntry[]` — `WHERE date >= ? AND date < ?` (first day of month, first day of next month); `childIds` filtered in JS after the query (a month is at most a few thousand rows; no dynamic `IN` lists).
- `applyChanges(changes: AttendanceChange[]): { saved: AttendanceEntry[], removed: { childId, date }[] }` — one `BEGIN IMMEDIATE`/`COMMIT` (`ROLLBACK` on throw); per change: `status === null` → `DELETE`, else upsert:

```sql
INSERT INTO attendance(child_id,date,status,reason,updated_at) VALUES(?,?,?,?,?)
ON CONFLICT(child_id,date) DO UPDATE SET status=excluded.status,reason=excluded.reason,updated_at=excluded.updated_at
```

  When the same `(childId, date)` appears twice in a batch the later one wins (spec: last write wins). `saved` re-reads the rows so `updatedAt` is the stored value.

`/** @typedef {ReturnType<typeof createAttendanceRepository>} AttendanceRepository */`

Tests (`:memory:` + `applySchema`, fixed `now`): `'upsert-ul pe aceeași zi înlocuiește starea și motivul fără să dubleze rândul'`, `'status null șterge rândul; ștergerea unui rând inexistent nu e eroare'`, `'listByMonth întoarce doar zilele lunii, filtrate după copii, ordonate după dată'`, `'o eroare la mijlocul lotului anulează tot lotul'` (second change has `date: null` → `NOT NULL` throws → first change not persisted).

### Task 5: Routes + `index.server.mjs` + composition

**Files:** create `src/features/attendance/server/attendance.routes.mjs` + `attendance.routes.integration.test.mjs`, `src/features/attendance/index.server.mjs`; modify `src/app/server/create-application.mjs`.

**Routes** (`createAttendanceRoutes({ database, recordRepository, now, today })`):

| Route | Input | 200 | 400 |
| --- | --- | --- | --- |
| `GET /api/attendance?date=` | `dateOK(date)` | `{ entries }` | data invalidă |
| `GET /api/attendance?month=[&groupId=][&childId=]` | `monthOK(month)`; `groupId` → ids of `readSnapshot().children` with that `groupId` (`'none'` → `null`); `childId` → `[childId]`; neither → all | `{ entries }` | lună invalidă; nici `date` nici `month` |
| `POST /api/attendance` | `{ changes: AttendanceChange[] }` | `AttendanceSaveResult` | vezi validarea |

Both GETs share one path: the handler branches on `url.searchParams`. POST validation, in this order, all with `fail(...)`: `changes` is a non-empty array of ≤ `MAX_CHANGES_PER_REQUEST`; each `childId` is a string and `recordRepository.exists('children', childId)`; `dateOK(date)`; `date <= today()` (`'Nu se marchează prezența pentru zile viitoare.'`); `status` ∈ `ATTENDANCE_STATUSES` or `null`; `reason` absent or string. Then `normalizeAttendanceChange` and `repository.applyChanges`. Nothing is saved if any change fails (validation precedes the transaction).

`index.server.mjs`: `export { createAttendanceRoutes }`, `export { createAttendanceRepository }`.

`create-application.mjs`: `...createAttendanceRoutes({ database: db, recordRepository })` in the `routes` array after `createSmsRoutes`.

### Task 7: `useAttendance` hook + `AttendanceDot` in `webapp/src/shared/attendance/`

**Files:** create `webapp/src/shared/attendance/index.ts`, `useAttendance.ts` (+test), `AttendanceDot.tsx` + `AttendanceDot.module.css`, `attendance-labels.ts` (`STATUS_LABEL: present → 'Prezent', absent → 'Absent', excused → 'Motivat', unmarked → 'Nemarcat'`, `STATUS_MARK: ✓ / × / M / ''`).

Types come from the backend file, as `useExcelTransfer.ts` already does: `import type { AttendanceEntry, AttendanceChange, AttendanceStatus, DayCellKind } from '#features/attendance/attendance.types.d.mts'`.

**Hook contract:**

```typescript
export type AttendanceQuery = { date: string } | { month: string; groupId?: string; childId?: string };

export interface AttendanceData {
  status: 'loading' | 'ready' | 'failed';
  failureMessage: string;
  /** Cheie attendanceKey(childId, date). */
  entries: ReadonlyMap<string, AttendanceEntry>;
  /** Aplică imediat în `entries`, trimite un singur POST după 400 ms cu ultima schimbare per copil·zi. */
  mark: (changes: AttendanceChange[]) => void;
  saving: boolean;
  /** Mesajul ultimului POST eșuat; pagina îl arată în toast. Se golește la următorul POST reușit. */
  saveError: string;
  reload: () => Promise<void>;
}

export function useAttendance(query: AttendanceQuery | null): AttendanceData;
```

Algorithm: `useEffect` keyed on `JSON.stringify(query)` → `requestJson('/api/attendance?…')` (`null` query → no request, `status: 'ready'`, empty map). `mark`: build the next `Map` (status `null` deletes, otherwise set with `updatedAt: ''`), merge each change into `pendingRef: Map<key, AttendanceChange>` (later wins), restart a 400 ms timer. `flush()`: take and clear `pendingRef`, `saving = true`, `requestJson('/api/attendance', { changes })`; on success merge `result.saved` (server `updatedAt`), clear `saveError`; on failure set `saveError = error.message` and `await reload()` so the screen shows the server truth. Unmount with a pending batch → flush immediately (the request outlives the component; nothing is lost on navigation). Clicks made while a flush is in flight go into the next batch.

`AttendanceDot`: `<span role="img" aria-label title className={styles[kind]} />` for `DayCellKind`; colours: `present → --success-dot`, `absent → --raspberry`, `excused → --yellow` (the spec's „galben” for Motivat; `#e0b400` from the mockup is not a token — use `--yellow-ink`-on-`--yellow` if contrast needs it), `unmarked → transparent + 1.5px --input-border`, `future → dotted --border`, `off/none → nothing`. 14 px in the grid, 10 px in the profile line (`size="sm"` prop).

Tests (stub `fetch` as `useExchangeRates.test`/`useSmsLastNotified.test` do; `vi.useFakeTimers()` for the debounce):
`'încarcă rândurile zilei și le indexează după copil|zi'`, `'mark schimbă starea imediat și trimite un singur POST după 400 ms, cu ultima schimbare per copil·zi'`, `'două mark-uri în 400 ms se cumulează într-o singură cerere'`, `'un POST eșuat pune saveError și reîncarcă de la server'`, `'query null nu face nicio cerere'`.

```typescript
  tone: PillTone;         // groupTone(groupId, groups)
  tiles: DayTileView[];
  present: number; unmarked: number;
}
export interface AttendanceDayData {
  status: 'loading' | 'ready' | 'failed'; failureMessage: string; saveError: string;
  counts: { present: number; absent: number; excused: number; unmarked: number }; // toate grupele, indiferent de filtru
  sections: DaySectionView[];   // după filtru
  groups: Group[]; groupFilter: string; setGroupFilter: (value: string) => void;
  cycle: (childId: string) => AttendanceStatus | null;   // întoarce noua stare (pagina deschide popover-ul când e 'excused')
  setReason: (childId: string, reason: string) => void;
  markGroupPresent: (sectionKey: string) => void;        // toți copiii grupei
  markAllUnmarkedPresent: () => void;                    // doar nemarcații, toate grupele
}
```

Reads `useAppSession()` for children/groups, `useAttendance({ date })` for entries. Enrolled children = `records.children.filter(child => isChildEnrolledOn(child, date))`; sections ordered by group name (`localeCompare('ro')`), „Fără grupă” last, only if non-empty; tiles sorted by name. `counts` = `summarizeDay` over all enrolled children. `initials` = first letters of the first two words (2-line local helper; `@features/children` cannot be imported).

**`DayView`** renders, top to bottom (00-comun §F padding, gap 18): the 4 `Card`s (Prezenți `tone="mint"`, the other three `white`; label 12/800 uppercase in the ink colour, number Baloo 30 `--slate`, zero → `--subtle`), `FilterPills` Grupa (Toate · groups with `groupTone` · Fără grupă) with `trailing` = the three-dot legend (Prezent / Absent / Motivat), then one section per group: `Badge tone={tone}` with the name, „N din M prezenți” + „ · K nemarcați” when K > 0, a `button` styled as link „Toată grupa prezentă” at the right, and a 5-column grid of `ChildTile`s.

**`ChildTile`**: a `<button type="button" aria-pressed…>` — avatar circle in the group tone (opacity .55 when absent/excused, as the mockup), name (ellipsis), state label in the state ink colour, right circle with ✓ / × / M (`--success-dot` / `--raspberry` / `--yellow`), unmarked = white circle with `--input-border`. Tile background/border: present `--mint-soft`/`--mint`, absent `--pink-soft`/`--pink`, excused `--yellow-soft`/`--yellow`, unmarked white/`--border`. `aria-label="{name}: {label}"`.

**`ExcuseReasonPopover({ childName, reason, onSave, onClose })`**: opened by the page when `cycle()` returns `'excused'` (and on click of an already-excused tile's „M” circle — optional; keep to the cycle if time is short). Small floating panel under the tile (`position: absolute`, shadow allowed — it floats), an input (max 200), two suggestion pills „Boală” / „Concediu” that fill the input, „Salvează” (primary) — Esc/outside click closes without changes. The reason goes through `setReason` → `mark([{ childId, date, status: 'excused', reason }])`, which the debounce merges with the status change into one POST.

States: loading → „Se încarcă datele…”; failed → message; ready with no enrolled children → „Niciun copil înscris la această dată.”; `saveError` → `useToast().show({ message })` from an effect.
