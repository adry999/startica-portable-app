# 04 — Vizite — val 2, pe design system

**Referință:** `docs/design/screens/04-vizite.md`, `Vizite.dc.html#4a`.

## Stare la intrare în val 2

Modulul era deja aproape complet migrat: `MonthCalendar`-ul propriu (cerut de spec cu `selected`/`cellHeight`, pe care componenta reală `@shared/ui/MonthCalendar` nu le are), `Card`/`Button`/`Badge`/`FilterPills`/`SegmentedControl`/`SearchInput`/`SearchSelect`/`SelectionBar`/`RowMenu`/`ConfirmDeleteDialog`/`DataTable` real (cu `onRowClick` nativ pentru selecția zilei), toate din `@shared/ui`. Rămăseseră de reparat: două date calculate cu `toLocaleDateString` brut (R7), trei texte de stare goală „Niciun/Nicio” hardcodate în afara catalogului (R9) și două fallback-uri hex redundante în CSS (R2, `var(--yellow-ink, #7a5d00)`, deși `--yellow-ink` are exact aceeași valoare în `tokens.css`).

## Ce s-a schimbat în această trecere

- **`VisitsPage.tsx` — R7**: `monthLabel()` folosea `new Date(...).toLocaleDateString('ro-RO', { month: 'long', year: 'numeric' })`; acum delegă la `formatMonthName()` din `#shared/format/date-format.mjs` + capitalizare locală, exact tiparul deja folosit în `children/BirthdaysPage.tsx`. `dayLabel()` (weekday+zi+lună, capitalizat) era identic cu `formatDayLabel()`, deja existent — funcția locală a fost eliminată, apelul înlocuit direct cu `formatDayLabel(visit.date)`. Niciun export nou necesar în `date-format.mjs`.
- **`VisitsPage.tsx` — R9 (text)**: cele trei texte hardcodate au fost înlocuite cu catalogul `empty-states.ts`, ale cărui chei (`vizite.day`, `vizite.month.rest`, `vizite.first`) existau deja, nefolosite:
  - Panoul zilei fără vizite: `<p>Nicio vizită programată în această zi.</p>` + `<Button>+ Programează vizită</Button>` → `<EmptyState size="compact" variant={EMPTY_STATES['vizite.day'].variant} title={resolveEmptyStateTitle(EMPTY_STATES['vizite.day'])} action={{ label: ..., onClick: () => setFormTarget('new') }} />`.
  - „Următoarele vizite” golit: `<p className={styles.dim}>Nicio altă vizită programată luna aceasta.</p>` → `<EmptyState size="compact" variant={EMPTY_STATES['vizite.month.rest'].variant} title={resolveEmptyStateTitle(EMPTY_STATES['vizite.month.rest'])} />`.
  - Tabelul „Toate vizitele”: `emptyState={<p>Nicio vizită nu corespunde filtrelor curente.</p>}` (text fix, arătat și când tabelul era gol prima dată, și când filtrele nu găseau nimic) → `empty="vizite.first"` + `hasActiveFilters`/`activeFilterLabels`/`onClearFilters` calculate din `search`/`statusFilter`/`showArchived`/`selectedDate`. `DataTable` alege acum singur „Fără rezultate” (generic, cu pastilele filtrelor active și buton „Șterge filtrele”) când există un filtru activ, respectiv catalogul `vizite.first` („Nicio vizită programată”) doar când tabelul chiar n-are nicio vizită înregistrată — distincție pe care textul fix n-o făcea. `onEmptyAction` a fost lăsat neconectat: catalogul `vizite.first` are `actionLabel: '+ Programează vizită'`, identic cu butonul deja fix din topbar (`useTopbarActions`) — un al doilea buton cu același nume accesibil ar fi dat coliziune de `getByRole` (confirmat de `App.test.tsx`, care aștepta un singur buton „+ Programează vizită”); fără `onEmptyAction`, `DataTable` arată doar titlul catalogului, fără CTA dublu.
- **`VisitsPage.module.css` — R2**: `.funnelYellow b { color: var(--yellow-ink, #7a5d00); }` → `var(--yellow-ink)`; `.pillProgramata { color: var(--yellow-ink, #7a5d00) !important; }` → `var(--yellow-ink)` (fallback-ul era redundant — `--yellow-ink` e deja `#7a5d00` în `tokens.css`). Eliminat și `.upcomingCard p { margin: 0; }`, rămas fără țintă după ce `<p>` a devenit `<EmptyState>`.
- **`architecture.test.ts`**: comentariu nou pe excepția R1 deja existentă (`visits/VisitsPage.tsx`, explicând de ce celula calendarului rămâne `<button>` propriu — vezi `INTREBARI.md`); `visits/VisitsPage.module.css` scos din R2 `ALLOWED` (fișier acum curat); `visits/VisitsPage.tsx` scos din R7 `ALLOWED` (fișier acum curat); `visits/VisitsPage.tsx` mutat din R9 `TEXT_ALLOWED` în R9 `IMPORT_ALLOWED` (nu mai are text literal „Niciun/Nicio”, dar are acum un import nou, legitim, al `EmptyState`/`EMPTY_STATES`/`resolveEmptyStateTitle`).

## Ce a rămas neschimbat, cu motiv

- **R1 — celula calendarului (`<button>` brut)**: hit-area pe toată celula (număr + pastile de vizite), cu stare „selectată” persistentă și mai multe pastile pe ton — pe care `MonthCalendar` din `@shared/ui` (existentă, dar neutilizată încă în `features/`) nu le suportă (n-are `selected`, n-are `cellHeight`, randează `div role="button"` nu `<button>`). `VisitsPage.test.tsx` selectează deja celula prin `button[class*="calendarCellToday"]` în trei teste — comportament testat, nu doar o scăpare. Detaliu complet în `INTREBARI.md` („Vizite — celula calendarului…”). Rămâne în R1 `ALLOWED`.
- **`VisitFormDrawer.tsx`, `EnrollDrawer.tsx`, `useVisits.ts`**: explicit în afara scope-ului acestei treceri (spec §1: „rămân”) — neatinse.

Nimic altceva de reparat: fișierul nu avea nicio încălcare R3 (caractere-iconiță) sau R4 (`lucide-react` doar în `Icon.tsx`).
